AESOP Transformation OS

Next.js 16 FastAPI Supabase Claude API Voyage AI

AESOP Transformation OS is a governance-first operating system for taking an enterprise from "we should use AI" to governed, evaluated, deployed, and monitored agents running at portfolio scale.

It closes two gaps that grow critical as organizations scale their agent portfolios: quality governance — no systematic way to evaluate safety, bias, and instruction quality at scale — and operationalization — technically sound agents fail when roles, adoption, and maintenance are never defined.

Every project flows through one connected pipeline, grounded in Organization context, then Discover, Working Agreement, Design, Build, Operationalize, Evaluate, Deploy, Repair, and Monitor — with all artifacts grouped under a project container for portfolio-level learning. The decision framework, The Eleven Tenets, is embedded as code at every gate, not just documentation.

How It Works — Pipeline

1
Organization — Ground the work in context
Establishes the organizational layer every agent is built against: departments, strategic priorities, and uploaded org context. From this foundation, the platform generates three context-aware reports: • Delegation of Authority Report — maps decision rights, approval hierarchies, and spending authorities across the organization • AI Adoption Roadmap — sequences implementation phases against business priorities and organizational readiness • Strategic Portfolio Kanban — ranks initiatives by impact, effort, and alignment to keep agent work tied to real business goals As new projects are added or organizational context changes, these reports can be regenerated against the updated context — so priorities, decision authority, and adoption sequencing stay current rather than going stale after the first project.
2
Discover — Validate the problem
A structured interview captures the problem, stakeholder map, and constraints, classifies the agent's autonomy level, and scores commitment readiness (capacity, response SLA, change appetite). It produces an Opportunity Brief and a GO / NO-GO / CONDITIONAL triage verdict before any build work begins.
3
Working Agreement — Gate the engagement
Before build, AESOP OS generates a signed Working Agreement from discovery data — scope, deliverables, response SLAs, and the RACI for the engagement. Design is hard-gated behind a signed agreement, with a manual override for internal projects.
4
Design — PRD and architecture recommendation
Generates a full PRD, then scores architecture options across platforms (Glean, Claude API, OpenAI, generic) with feasibility analysis. An 11-dimension gap analysis flags missing or infeasible requirements before build.
5
Build — 6-phase instruction writing with HITL
A six-phase pipeline (fitness check, gap analysis, workflow design, instruction writing, artifact export, summary) writes the system prompt with a human-in-the-loop approval checkpoint. Outputs include platform-specific artifacts plus a State Change Hypothesis, Translation Debt Assessment, and Ripple Map.
6
Operationalize — Launch package generation
Generates the org infrastructure to actually run the agent: a RACI matrix, a plain-language Tiger Team Brief, a Maintenance Plan tied to autonomy level, and a phased Adoption Plan calibrated to commitment readiness — all from data already captured in the pipeline.
7
Evaluate — Seven complementary evaluation modes
Quality is assessed through seven distinct modes, not one pass: (1) Standard Analysis — a 5-agent pipeline scoring Instructions, Ethos, Bias, and Safety with a Synthesis pass, where Tier-1 dimensions (Safety, Bias) carry 1.5x weight and a hard veto caps the score if either falls below threshold (2) Cave of Shadows — red-team adversarial testing with attack personas probing boundary violations (3) Custom Rubric — domain-specific weighted criteria generated from the agent's own instructions (4) Hydra — functional regression testing firing parallel scenarios against live endpoints (5) Bias Probe — differential fairness testing across demographic variations (6) KB Audit — knowledge-base completeness and coherence checks for retrieval agents (7) Trace Analysis — replays and inspects agent decision paths to verify reasoning fidelity, detect drift in judgment patterns, and surface hidden failure modes that pass output-only evaluation Certification spans Bronze through Platinum.
8
Deploy — Ship to the target platform
Certified agents ship to their target platform through pluggable connectors (Glean, Claude API, OpenAI, generic REST), packaged with the operationalization artifacts so the organization deploys with clear ownership, an adoption plan, and a maintenance schedule in hand.
9
Repair — Extended-thinking rewrite
When monitoring or evaluation surfaces issues, the Repair agent uses extended thinking to analyze failures and Tiger Team findings, then rewrites instructions with rationale and a tracked change summary — closing the loop between live feedback and improvement.
10
Monitor — Track health and drift in production
Continuous portfolio monitoring: score trajectories, version diffs, per-agent and aggregate cost tracking, an organization-wide agent health dashboard, and a maintenance schedule with drift alerts, stale-evaluation warnings, and scheduled re-evaluations.
