AESOP Transformation OS

A platform that helps organizations move from “we know we should use AI” to actually running governed, trusted AI agents across the business.

How it works

1

Ground the work in your organization

Before anyone builds anything, AESOP captures how your organization actually works — departments, priorities, where work gets stuck. Three lenses together: the context you operate in, the research that informs decisions, and the discovery of what’s actually needed.
In the app: An admin dashboard with portfolio KPIs, an organization context library, a department roster, and a strategic prioritization view that scores AI project candidates.
ContextUpload org charts, strategy docs, process maps. Define departments, team members, and decision rights. The platform builds a living model of how your organization operates.
ResearchAI Adoption Roadmap auto-generated from your context. Delegation of Authority Report maps who decides what. Strategic Portfolio Kanban visualizes all projects: Backlog, On Deck, In Progress, Done.
📏
Metrics: Portfolio health tracked via project count per stage, average time-in-stage, and adoption readiness score. These baselines set the benchmark that stages 7 and 8 measure against.
2

Secure management sponsorship with a Working Agreement

Every initiative lives inside a project container. Before design starts, a Working Agreement locks in scope, responsibilities, and a north star metric — ensuring leadership commitment exists before resources are spent.
In the app: Create a project, define a north star metric (what does success look like?), then generate a Working Agreement from a template. It auto-fills stakeholder names, autonomy level, and commitment scores from discovery data. Design is locked until the agreement is signed — with an override for internal projects.
  • Pipeline progress bar shows green checkmarks for completed stages, amber spinners for in-progress
  • Working Agreement status: draft → sent → signed
  • North star metric is the thread that runs through every subsequent stage
📏
Metrics: North star metric defined here — a single measurable outcome that answers “what does success look like?” Example: “Reduce contract review turnaround from 14 days to 2 days.” This metric is referenced at every gate: Design (can we achieve it?), Build (does the agent target it?), Evaluate (did we hit it?), and Monitor (are we still hitting it?).
3

Validate the problem before you build

A structured interview walks through the problem, the stakeholders, and the constraints — then gives a straight answer: go, no-go, or conditional. Data from stages 1 and 2 (org context, north star) feeds directly into the interview.
In the app: A guided interview screen with structured questions. The system classifies how autonomous the agent should be and scores commitment readiness across three dimensions: does the team have capacity, will they respond quickly enough, and can they absorb the change?
  • Opportunity Brief auto-generated from interview answers
  • Triage verdict: GO, NO-GO, or CONDITIONAL — with the reasoning visible
  • Stakeholder map captured: executive sponsor, project owner, affected groups
📏
Metrics: Commitment readiness scored 0–100 across three dimensions (capacity, responsiveness, change appetite). Scores below 60 trigger a CONDITIONAL verdict. North star alignment is checked: does the discovery brief actually target the metric defined in the Working Agreement?
4

Design the right solution

From the opportunity brief, AESOP generates a full PRD and scores which AI platform is the best fit — not defaulting to whatever tool you already have.
In the app: A PRD document generated from the discovery brief. An architecture recommendation card scores each platform option (Glean, Claude API, OpenAI, custom) across feasibility, capability, and fit. An 11-dimension gap analysis flags missing or infeasible requirements.
  • Side-by-side platform comparison with scores and rationale
  • Gap analysis: red flags for anything that can't be built as specified
  • PRD can be downloaded as Markdown for sharing outside the platform
5

Build the agent — with a human checkpoint

A six-phase pipeline writes the agent's instructions. A human must approve before the build proceeds past the gap analysis. You see every phase stream in real time.
In the app: A build page showing six phases with real-time streaming progress. Phase 1 (Gap Analysis) halts for human approval — a big "Approve" button, not a silent automation. Nine quick-start patterns (Q&A Bot, Workflow Agent, Approval Workflow, etc.) let you skip the blank page.
  • Phase 0: Fitness Check — auto-stops if the platform can't support this agent
  • Phase 3: Write Instructions — the actual system prompt, visible and editable
  • Phase 5: Summary — what will change, what could go wrong, what ripple effects to watch for
6

Evaluate before you deploy — with a hard safety gate

Seven different ways to test the agent. If safety or bias scores drop below 75%, the agent cannot ship. This is enforced by the platform, not left to judgment calls.
In the app: An evaluation dashboard showing per-dimension scores, a certification badge (Bronze through Platinum), and a pass/fail verdict with the veto rule visible. Each evaluation mode has its own interface — red-team attack personas, custom rubric builder, bias probe scenario configurator.
  • Standard Analysis: 5 evaluators score Instructions, Ethos, Bias, Safety — with weighted scoring
  • Cave of Shadows: adversarial testing with attack personas probing boundary violations
  • KB Audit: per-document issues and suggestions for retrieval agents
  • Evaluation reports downloadable, all findings link back to source evidence
📏
Metrics: Certification score (Bronze 75+, Silver 80+, Gold 85+, Platinum 90+). Hard veto: if Bias or Safety falls below 75, the total score is capped at 74.9 regardless of other dimensions. North star metric is evaluated: does the agent’s output actually move the needle defined in stage 2?
7

Give the organization what it needs to adopt the agent

A technically perfect agent that nobody uses is a failure. AESOP generates the documents your organization actually needs to deploy, adopt, and maintain the agent — using data it already collected.
In the app: A "Generate Launch Package" button on the Build page. One click produces four documents. Each can be expanded inline, downloaded as Markdown, and marked as reviewed. Tiger Team feedback can be pasted directly into the Repair workflow.
  • RACI Matrix: Who is Responsible, Accountable, Consulted, Informed for every activity
  • Tiger Team Brief: A 5-minute read for stakeholders — what changes for them, what's needed
  • Maintenance Plan: Evaluation cadence, drift thresholds, decommission criteria
  • Adoption Plan: Phased rollout calibrated to how ready the organization actually is
📏
Metrics — calling back to stage 2: The Adoption Plan includes a target for the north star metric defined in the Working Agreement. If the metric was “reduce turnaround from 14 days to 2 days,” the adoption plan specifies: measure baseline before rollout, track weekly during phased adoption, and define the threshold that counts as “adopted.” → Stage 8 monitors these same metrics continuously.
8

Monitor, repair, and improve

Once agents are live, AESOP tracks how they're performing, what they cost, and whether they're drifting. When scores drop, the Repair workflow analyzes failures and rewrites instructions.
In the app: A portfolio health dashboard showing all agents with current scores, cost tracking, and drift alerts. The Repair page lets you paste evaluation reports and Tiger Team findings, then runs an extended-thinking analysis to produce rewritten instructions with a tracked change summary.
  • Score trajectory charts show improvement (or decline) across evaluation iterations
  • Version history with diffs for all agent iterations
  • Drift alerts: score below certification threshold, 30+ days since last evaluation
  • Cost tracking: per agent, per evaluation, and in aggregate across the organization
📏
Metrics — calling back to stage 2: North star metric time-series charts show whether the agent is still delivering on the outcome defined in the Working Agreement. Adoption metrics from stage 7 are tracked: is anyone actually using it? Drift alerts fire when the north star metric degrades, triggering a Repair workflow that rewrites instructions to close the gap. ← Full loop from define (stage 2) → target (stage 7) → track (stage 8) → repair.
