AESOP — Enterprise AI Agent Governance

Context Architecture

What AESOP knows is limited by what it was given to read. Here is what it collects, where the rest comes from, and what actually changes because of it.

01

The contextfour layers

Context arrives in four layers. You only fully control the first one.

Layer 01The agent
What you are testing The system instructions, the agent's name, and an endpoint if you want it exercised live.
Layer 02The policy layer
What it gets measured against Governance documents you pick from the shared library or upload on the spot. Pick none and your organization's own policy is used instead.
Layer 03The run frame
What this run is for Notes on the agent's real situation, the failure modes you already suspect, and the rubric, either generated or supplied.
Layer 04The audience
Who the agent acts on Who they are, what state they are in, how vulnerable they are, and whether they deal with it once or for months.
The six reviewers never see this layer. Only the human-impact scorers do, so a sympathetic audience cannot soften how the instructions read.

Transcripts from Teams, Zoom, Granola, or Otter. The platform pulls out risks, decisions, and changes, each carrying the quote it came from. Nothing counts until a person approves it.

The endpoint and its credentials are read from the agent, not typed into the run. A password entered once does not become the one that gets used.

04

What the context changesinput → effect

Collecting context only matters if it moves the answer. Here is what each piece actually does.

System
instructions
The only input that sets how confident the review is allowed to sound. Length alone decides it. Under 500 characters and the report says so.
Governance
documents
Appended to the instructions, so every reviewer reads them. Legal and InfoSec are told to check the instructions against them specifically. They also make that text longer, which raises the confidence band.
Vital
context
Two different jobs. The six reviewers use it only to adjust confidence, it never reaches their prompt. Red-team uses it as the boundary every attack has to fall outside.
The
audience
Human Impact will not run without it. The scorers read the conversations, not the description, so the score is what the agent did rather than what the reader expected.
Prior
runs
Red-team stops rediscovering the agent. The second evaluation is cheaper and sharper than the first, because it aims at what is already known instead of starting over.
Trace
taxonomy
People code real traces by hand, the codes get consolidated, and a person approves the taxonomy. Only then is a judge built for each one. The result is traceability: every repair cites a named code with its evidence attached, so you can walk a fix back to the conversation that justified it.
The honest limit. Context raises confidence. It does not measure correctness. Instructions and governance both move the confidence band by length, which tells you how much the platform had to read, not how right it is. The judgments that rest on evidence come from traces and prior runs. Everything else is framing.
