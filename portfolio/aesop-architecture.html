AESOP — Enterprise AI Agent Governance

Context Architecture

What AESOP knows is bounded by what it was given to read. This page maps what context the platform gathers, where each piece comes from when you never type it, which evaluation mode asks for what, and what actually changes downstream because of it.

01

The contextfour layers, one run

Context arrives in four layers. Only the first is ever fully in your hands. The other three are assembled from what the platform already holds, and each one changes a different part of the result.

Layer 01The agent
What is being tested
  • System instructions. The object under test. Upload, paste, or read from the agent record.
  • Agent name. Also becomes the run name.
  • Endpoint URL and auth header. Optional. Providing it unlocks the live modes.
  • Instruction version. Detected on create, so a run can be tied to a version later.
Layer 02The policy layer
What it is measured against
  • Governance documents. Selected from a shared library or uploaded on the spot. PDF, DOCX, TXT, MD, XML, up to 10MB.
  • Document type. Governance, policy, standard, compliance, validation protocol, change control, risk register, audit SOP, regulatory template.
  • Org fallback. If you select nothing, the organization's own governance policy and evaluation criteria are used instead.
Layer 03The run frame
What this particular run is for
  • Context for this run. Free prose about the agent's real situation.
  • Focus. The failure modes you already suspect, to aim the scenario writers.
  • Rubric. Generated by the platform, or supplied by you as YAML, JSON, TXT, or MD.
  • Modes and reviewers. Which evaluation types run, and which of the six reviewers score the instructions.
Layer 04The audience
Who the agent acts on
  • Who it serves. Required whenever human impact is selected.
  • What state they are usually in when they arrive.
  • How vulnerable they are. Low, mixed, or high.
  • How long they interact. One-off or ongoing.
This is the only context the six reviewers deliberately never see. It reaches the human-impact dimension scorers and nothing else, so a calm reading of the instructions cannot be contaminated by how sympathetic the audience is.

Three ways context gets in. You type it for the run, the platform inherits it from your organization and your past runs, or it is observed from production.

Eighteen typed slots that describe the business rather than the agent: company profile, strategic goals, brand guidelines, org chart, authority map, coordination map, tacit knowledge, exposure posture, systemic blockers, stakeholder interviews, and the rest. Each holds text or a file. This is the layer that makes a finding land in your world instead of in the abstract.

Prior
runs
The platform remembers what it already established about this agent.
  • Reuse last context. The previous run's vital context, audience, and supplied rubric are offered back, pre-filled, with a box to uncheck.
  • Prior reports. Red-team aims at what is already known instead of rediscovering the agent from zero.
  • Prior failures and scenarios. Known defects get targeted, and scenarios already run are not repeated.
  • Finding history. Across a rolling window of the last five runs, every failing finding is classified as a regression, a repeat, or new.
Production
traces
Real conversations, pasted or imported. The parser accepts User/Agent, Human/Assistant, Q/A, and JSONL, and falls back to a model-based parser for formats it does not recognize. Duplicates are dropped on their external id.
  • Stored per agent with turn index, latency, token usage, and error or refusal flags.
  • These are the traces the human coding pass and the model judge both read.
Meeting
transcripts
Paste or upload a transcript from Teams, Zoom, Granola, or Otter. The platform extracts proposed changes, each with the source quote, a confidence, the speaker, and the meeting it came from: status changes, milestones, new and updated risks, budget, timeline, scope, decisions, and action items.
Review status pending → approved / rejected / modified
Nothing extracted from a transcript is treated as fact until a person approves it. The quote travels with the claim so the approval is a reading, not a guess.
Agent record
& project
The endpoint and its auth are read from the agent record at run time rather than trusted from the form, so a credential typed into a run does not become the thing that gets used. When a run is linked to a project, the project's north-star metric comes with it.

Measure its effect
on the personNeeds endpointNeeds the audience fieldsNeeds a scenario phase first
Human Impact. Reads the conversations the agent actually had and scores what they did to the person in them.
This one is a real dependency, not a preference. It judges transcripts nobody else produced. With no scenario phase there is nothing to read, and a phase with nothing to read reports nothing, which looks exactly like a clean result. The discovery interview does not satisfy it either: what the interview produces is not the kind of transcript this reads.
04

What the context changesinput → effect

Gathering context is only worth the trouble if it moves the answer. Each entry below names the mechanism, not the intention.

System
instructions
The object under test, and the only input to how confident the review is allowed to sound. Length alone sets the band: under 100 characters is the lowest band, under 500 the next, under 2,000 the next, and 2,000 or more the highest. Below 500 characters the report prints a caveat saying so.
Read by all six reviewers → confidence band
Governance
documents
Appended to the instructions under a governance header, so they reach every reviewer. Two of them are told explicitly to evaluate the instructions against the documents: Legal Compliance and InfoSec. Because they are appended, they also lengthen the instruction text, which moves the confidence band up.
Read by all six reviewers → criteria + confidence band
Vital
context
Two entirely different jobs depending on who is reading.
  • For the six reviewers, it never enters the message. It adjusts the confidence score and nothing else.
  • For red-team, it is the declared audience. Every off-audience scenario must fall outside it.
  • For synthesis, repair, and the test plan, it is prose to write against.
The
audience
A hard precondition. Without the audience fields the human-impact phase is skipped entirely rather than run on a default. The four calibrated scorers read the conversations; they never read the audience description itself, so the score is what the agent did, not what the reader was told to expect.
Prior
reports
Red-team stops rediscovering the agent. Scenarios are aimed at what earlier runs already established, which is what makes the second and third evaluation of an agent cheaper and sharper than the first.
Prior failures
& scenarios
Known defects get targeted and already-run scenarios are skipped, so a repeat evaluation spends its budget on the part of the surface that is still untested.
Trace
taxonomy
Traces are coded by hand, the codes are consolidated, and a person approves the taxonomy. Only then does it become real.
Then a judge is built per code → validated against the human annotations → run across every trace
  • A judge returns exactly three verdicts: occurred, did not occur, or not applicable. The escape bucket is mandatory, enforced at import.
  • Validation produces a confusion matrix against the human coding: recall, precision, specificity, agreement.
  • The approved taxonomy is the only version that feeds repair and the test plan.
The effect is traceability. Every rewrite the repair agent proposes cites a named code with its evidence attached, so you can walk a fix back to the conversation that justified it.
The honest limit. Context raises confidence; it does not measure correctness. Instructions and governance both move the confidence band by length, which is a statement about how much the platform had to read, not how right it is. The behaviors that actually ground a judgment are the ones read from production: traces, transcripts, and prior runs. Everything else is framing.
