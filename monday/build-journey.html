Stage 1 Board Structure
Created the 3-board skeleton. Intake Board (form backing, 10 columns), Portfolio Board (PM strategic view, Status pipeline), and Execution Board (tactical, Sprint-based groups). The structural contrast is deliberate — Portfolio uses a Status pipeline, Execution uses Sprint groups. That satisfies the assignment's "structured differently" requirement by design, not by accident.

Stage 2 Intake Flow
Built the public-facing intake form — 8 fields, all mapped to the assignment text. On submission, an item lands on the Intake Board. AI Summary and AI Completeness columns fire automatically. The Completeness formula routes to Portfolio or back to the submitter.

Stage 3 Automations
Wired 5 automations across Intake and Portfolio: AI completeness routing, field completeness routing, SLA breach notification, PM assignment, and Execution Board creation on approval. The SLA breach is the live demo moment — when the Evaluation Deadline arrives with no decision, the PM and Pepper get notified immediately.

Stage 4 Executive Dashboard
4 widgets, all live, all fed directly from board data — Portfolio Health (pie), SLA Compliance (number), Active Projects (table), Department Load (bar). Zero manual work for Pepper. No spreadsheets, no PowerPoint. The dashboard updates as items move through the pipeline.
Full diagram →
Stage 5 AI / Formula Separation
Two distinct layers. AI handles fuzzy — the AI Summary column reads the Business Problem, the AI Completeness column judges whether the request has enough info. Formula handles deterministic — checks if required fields are filled. Each tool does what it's good at. Discovered that formula columns can't trigger automations directly — the workaround became a platform fluency talking point.
Full diagram →
Stage 6 Connected Architecture
Linked all 3 tiers with Connect Boards. Intake → Portfolio (request triage). Portfolio → Execution (work assignment). Mirror columns feed Status and Due Date back up so PMs see trajectory without clicking through. What rolls up vs. what stays local is deliberate — executives see trajectory, not micro-detail.

Stage 7 Demo Test Plan
Injected 6 Stark Industries mock requests via API. 3 demo scenarios: approval path (Arc Reactor — one click triggers the full pipeline), SLA breach (Palladium — watch the notification fire live), and rejection path (Ping Pong — "no" is fast). 30 minutes total: 10 min walkthrough, 15 min demo, 5 min Q&A buffer.
