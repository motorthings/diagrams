Monitor · Production

Catch the drift before the customer does.

An agent ships, then it drifts. Last week it was right; this week a stale article wins and the wrong number comes out. Monitoring is the loop that names the failure mode and closes the gap.

Thumbs up, thumbs down can't do it. You need a baseline, a delta, and a way to trace the signal back to the source that broke.

Five failure modes to watch

Hallucination
No grounding
A confident answer with no source under it at all.
Retrieval failure
Wrong document
The wrong doc pulled, or the right one never surfaced.
Attribution error
Wrong source
A right-looking answer built on the wrong source. The wrong phone number.
Recency
Stale article wins
A superseded document favored over a newer one.
Guardrail breach
Off-policy
Break character, leak instructions, unsafe or biased output.

Two layers, one signal

Deterministic
Can't hallucinate
Entity and format checks, source-date freshness, guardrail rules. The wrong-number bug dies here because it's structural, not semantic.
Probabilistic
Judges over the semantic
Hallucination, attribution, off-policy. Scored, not binary, run over every trace.

What's missing now

01No failure-mode taxonomyDrift is one number from one agent. You can't see which mode moved.
02No baseline / deltaMeasured against the instructions, not against last week's prevalence.
03No deterministic layerIt's all one LLM. The wrong number isn't caught structurally.
04No scheduled sweepsManual only. No cadence, no trigger on a model or knowledge change.
05No repair wiringAlerts and the repair loop are disconnected. The delta never closes.

Build phases

Phase 0
Baseline + delta
Per-mode prevalence per sweep, so drift is a delta, not an absolute.
Phase 1
Deterministic layer
Entity, format, freshness checks with no LLM. Catches the named bugs structurally.
Phase 2
Per-mode judges
Replace the single drift agent with a judge per failure mode.
Phase 3
Scheduled sweeps
Cadence plus triggers on model update, knowledge change, prompt change.
Phase 4
Repair wiring
Alert feeds the repair loop; re-measure shows the delta closed.
Phase 5
Dashboard
Render the per-mode prevalence delta. The thing the operator reads.

The demo: two epochs, one delta

Epoch 1
Clean knowledge base
Sweep. Baseline prevalence near zero. Deterministic checks green.
Epoch 2
Inject a stale article + a transposed number
Sweep. Deterministic checks red, recency and attribution prevalence up. The delta is the signal.
Honesty, not magic. Monitoring here is periodic re-evaluation and drift comparison, not continuous stream ingestion — you can't live-instrument a vendor agent from outside. The demo runs on a synthetic two-epoch fixture built to reproduce two real failure modes. That's a true claim about what the structure catches, not a claim the whole loop is proven in production.
