The Databricks Index Layer

Thirty synthetic documents, each carrying governance frontmatter. One script parses them, rejects the ones missing a governance field, and lands one row per chunk in a Delta table.

A Vector Search index mirrors that table with managed embeddings. The governance fields ride along as columns. They are what let the monitor's checks fire.

Storage — the docs, the table, the index Compute — the gate and the query Consumer — the monitor that reads

Markdown in, a governed table out

Each document is markdown with YAML frontmatter. The frontmatter is the governance. Without it the document is just text, and text cannot answer whether it is current or whose rules it states.

The index is a mirror of the table, not a place to stash metadata at write time. Every governance field has to exist as a column first, because the index copies columns out of the table.

Step 1
Parse the frontmatter
Each file is split into its metadata block and its body. A file with no frontmatter at all is not a KB document and is skipped. A file with partial frontmatter is a real gap.
Step 2
Validate against the contract
Thirteen fields are required. Missing a jurisdiction or an effective date fails. A value outside the allowed set, like a state that is not CO, MN, WI, TX, or NM, fails too.
Step 3
Chunk and land rows
Each document is split on headings, then paragraphs, into deterministic chunks. Every chunk becomes one row, every governance field its own column.
Step 4
Sync into the index
A DELTA_SYNC index reads the table, embeds the text column with a managed model, and attaches the governance columns so they can be filtered on and read back.

The gate: incomplete governance never ingests

Metadata is the governance, so a document missing it must not slip in silently. The script fails loudly by default. It prints which document is short, and which fields, and aborts before anything is written.

There is a second mode. --on-incomplete=flag ingests the document anyway and marks its rows governance_complete=false. The gap stays visible in the table instead of hidden in a file. Either way, the gap is recorded, never swallowed.

A missing field is not a formatting problem. If a document has no jurisdiction, the scope check has nothing to compare against. If it has no effective_from, freshness cannot see whether it governs today. Rejecting the document at the gate is what keeps those checks from silently passing later.

Why the columns live in the table

Databricks Free Edition allows one Vector Search endpoint, one search unit, and no Direct Vector Access. The only available shape is a Delta-sync index with managed embeddings.

That constraint decides the architecture. A Delta-sync index is a copy of a table. It cannot hold metadata that the table does not have. So the governance fields have to be columns in the Delta table, and the index syncs them out.

The load-bearing part: columns_to_sync

Fourteen governance columns are attached to the index, plus the passage text. Attached means two things. Retrieval can filter on them. And every result carries them back to the caller.

The remaining synced columns are title, owner, source_ref, and last_updated, plus the text the embeddings are built from. topic and claim are the ones people forget. Without a shared topic, the contradiction and authority checks have nothing to group on and cannot fire at all.

One layer of two the monitor reads

This layer attaches the facts. The retriever carries them into the trace. The monitor compares them against fixed rules and returns the same finding every time.

How this layer feeds the AESOP monitor. The governance columns are synced onto the index, so every chunk a query returns arrives with its status, jurisdiction, operating company, authority, dates, topic, and claim attached. The monitor's freshness, scope, authority, and contradiction checks read exactly those columns. Drop one from columns_to_sync and the matching check goes quiet. The columns are not documentation. They are the wiring.
