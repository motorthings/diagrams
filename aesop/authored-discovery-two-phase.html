Two-Phase Authored Discovery

Map what exists. Then question whether it should exist. Before anything gets built.

Foundation

Every org chart is a fossilized set of workarounds for human limits.

Departments exist because one person can only hold so much expertise. Hierarchies exist because a manager can only coordinate so many people. Meetings exist because context lives in heads and has to be moved between them. Approvals exist because judgement is expensive and you can't trust everyone with it.

This isn't new thinking. But the implication for AI is: every one of those structures is now optional.

Most "AI transformation" pours intelligence into the fossil faster. AESOP asks whether the fossil still makes sense.

Two Approaches to Discovery

Phase 1: Inherited

Where most platforms stop

  • Maps current process step by step
  • Captures existing roles, approvals, meetings
  • Asks: "How does this work today?"
  • Produces a brief based on the inherited org chart

Phase 2: Authored

What makes AESOP different

  • Questions which roles exist because of old constraints
  • Maps decisions, not departments
  • Separates real constraints from inherited ones
  • Asks: "What would you design from scratch?"
  • Enriches the brief with assumptions challenged

Why This Matters

The replication trap: Everyone's racing to post agent counts on LinkedIn. "I wake up to 14 agent updates every morning." That's not transformation. That's a faster status meeting. You built a quicker horse and called it a car. Nobody posts "I dissolved the approval layer." Nobody brags about the role they made obsolete. Agent count answers what the technology can do — the boring question. The real one: what kind of organization becomes possible when judgement and context stop being scarce?
01

Structure as output, not input

Inherited treats the org chart as fixed. Authored treats it as the thing under question.

02

Replication vs. dissolution

If removing the agent means going back to the old way, you replicated. If it makes you realize the role was never needed, you dissolved.

03

Legibility bias

Automating a standup produces a demo. Questioning why the standup exists produces a redesign. Scarier, slower, essential.

04

The only question that matters

Replace a person, or dissolve the reason the role existed? If you can't answer that, you're automating — not transforming.

"Does this agent replace a person, or does it dissolve the reason the role existed?"
If you can answer, you're authoring the organization. If you can't, you're automating the old one. AESOP forces this question before anything gets built.
