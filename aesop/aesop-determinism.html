Where the model stops and Python starts

The pipeline used to ask a model for an essay, then pay Python to read the essay back and guess at what it meant.
Not anymore. Here is what moved, what it cost, and what is still wrong with it.

01 The defect three ways the guessing showed up

None of these were hypothetical. Each one shipped, ran on real builds, and was found by reading the code against the output it produced.

Same answer, two verdicts

Four parsers, two pipelines, no agreement

Two copies of the verdict parsers had drifted. One excluded the words blocker and blocking; the other did not, so a sentence about the absence of blockers could read as a block. A second copy regexed a whole document for the word fail, so any mention anywhere returned fail.

The verdict gates a point where a human has to approve. The difference was not cosmetic.

A number scraped from prose

“3/100” became a score of 3.0

A fallback pattern in the score extractor matched any number-over-100 anywhere in a report. “We reviewed 3/100 documents” wrote 3.0 into a score column. The fallback was defensible when written and wrong when read.

It is deleted now. Deleting it was the fix.

Re-deriving what was already known

One dict, three prose copies

The discovery answers are clean JSON. They got flattened to markdown once, stored, then flattened again by the next stage and stored again, then copied a third time. Three encodings of one structured record, each re-parsed by whoever needed it.

No model was involved. It was still waste, and three places to drift.

02 The rung ladder how to pick where a decision lives

Every decision in the pipeline sits on one of three rungs. The rung is not about how hard the decision is. It is about who is allowed to make it.

Rung 0 · a rule

Python decides

Deterministic, cheap, instant, testable. It also cannot read a paragraph. A rule is only available when the input is already structured, and most of what arrives is not.

Rung 1 · prose

The model writes, Python scrapes

The model can read anything and promises nothing. You ask for a narrative, then hunt the verdict back out of it with a regular expression. This is where the three defects above live. It is the default because it is the easiest thing to write.

Rung 2 · a structured field

The model judges, Python decides

The model emits a closed label or a set of named numbers. Python branches on the label. The judgment stays with the model because it is genuinely a judgment; the arithmetic and the rule order move to Python, where they can be tested.

The one rule that keeps rung 2 from drifting back

When a numeric spec exists in Python, the prompt is rendered from that spec. The weight table, the thresholds, the band boundaries, the mandatory-fail list, all of it lives in one module and the prompt text is generated from it.

That is the whole trick. A prompt and a Python constant describing the same thresholds are two facts that happen to agree today. Render one from the other and they cannot disagree tomorrow.

04 Phase 0, in full precedence the model cannot override

Phase 0 asks one question: is this project fit to build? The rubric has five weighted signals, a go threshold, a conditional floor, and five conditions that fail a build outright.

The prompt used to carry all of that as prose — the weight table, the thresholds, the rules — and Python then scraped the verdict back out of the model’s answer. Now the model reports the subscores and names any mandatory failure it found. Python applies the rubric.

Precedence runs top to bottom. The first rule that fires decides, and the ones below never run.

05 Jev, and the escape hatch the strongest part, and the honest one

Rung 2 needs a model that returns a label from a closed set rather than a paragraph. That model is Jev — TypeSafe’s flagship structured-decision model. You hand it a question and a map of options; it returns one option plus a probability distribution over all of them.

A service, not a connector

Three structural reasons, written into the module

  • Wrong shape. send_message(...) -> ConnectorResponse is chat-shaped. A typed question map returning a probability distribution has nowhere to go in that dataclass.
  • Wrong trust boundary. Connector URLs are user-supplied, which is why they get an SSRF check. This endpoint is ours, fixed, and must never be repointable.
  • Wrong lifetime. Connectors model per-user endpoints. This is one shared internal client, the same category as the LLM provider service.

The docstring says all three, so nobody later “tidies” it into the connector factory.

Determinism, honestly stated

Statistical determinism

There is no temperature and no seed parameter. The module says so in its first paragraph rather than implying a guarantee it cannot make.

Jev’s measured behaviour is good: 100% label agreement over 15 repeats, score standard deviation around 0.005. Run-to-run stability is not correctness on a hard input, and the docstring says that too.

We also send the floating tag jev-latest rather than a pinned build, so every number on this page is of whichever build that tag resolved to on the day. A floating tag can move under a measurement.

The measurement that changed the design

A closed set of options has a failure mode you do not see until you look for it. If none of the labels fit the input, Jev still has to return one. So it picks the closest.

Measured: out-of-scope input with no none-of-the-above option was filed into a real category at 0.980 and 0.990 confidence. That matters more than it sounds. Any rule of the form confidence below a threshold, escalate is a no-op for exactly the traffic you most want escalated — Jev is confident, and wrong.

So the escape hatch is enforced at construction. decide_choice raises before any network call if the option map has no none-of-the-above key. A future call site cannot reintroduce the hole by forgetting, because forgetting is a hard error.

Then I measured it again, against production

That is the version in the design doc. Here is what happened when the same function was run against the real endpoint — jev-latest, four runs per input.

The guard does not do what the plan said it would. The construction-time check forces a none-of-the-above option to exist. It does not make Jev choose it. Two of three out-of-scope inputs were filed into a real pattern, every time. One of them at 0.91 confidence, so a confidence-threshold rule would not have caught it either.

The sample is four runs. That is a signal, not a measurement, and the page says so rather than rounding it up into a claim. What it is enough to do is stop the rollout.

Status of the rollout
  • Shadow mode, not on. STRUCTURED_DECISION_PATTERN_MATCHER defaults to shadow. Both paths run, disagreements are logged, and the keyword result is the one used
  • Shadow is the right default for a reason. The first production line reads pattern_matcher=shadow keyword=Workflow Agent structured=Workflow Agent agree=True — one line, one agreement, no disagreement rate yet characterized
  • What would flip it. A disagreement rate over real briefs. Until that number exists, the honest setting is the one that cannot change a build
06 The cache inversion paying to save

Prompt caching keys on a prefix hash. A breakpoint caches everything from the start of the prompt through that breakpoint. Anything that varies ahead of a breakpoint invalidates everything behind it.

The system block varied per phase, because each phase pulled a different set of knowledge docs. The PRD breakpoint sat after it. So the PRD’s own prefix included the block that had just changed, and the cache missed on every phase of every build.

The part that looks like a mistake and is not. A role-only system block is roughly 500 tokens. The minimum cacheable prefix on the model in question is 2,048. Below that floor, caching does not error — it silently does nothing. So the eight root methodology docs are deliberately included on every phase, including the phases that previously received no docs at all. Phases two through five each pay about 16K tokens at a tenth of the price, and in exchange the whole 16K-token prefix plus the PRD behind it becomes cacheable across all seven phases.
And that is a real change to what the model sees. Phases two through five now receive eight methodology documents they did not receive before. It is a cost change and a behavior change. The docs are relevant to writing instructions, so it should help. It has not been validated on a build, and the first fullstack build after this shipped is the test. The module says exactly that, in the code, next to the decision.

The instrumentation came before the fix, for a reason: the numbers had to be observable before anyone could claim they had improved. One log line per phase, readable out of the deploy logs, is what makes the whole section above checkable instead of asserted.

08 What the pass was actually worth the short version

Four things were true at the start and are not true now.

One, not four

The verdict is decided in one place

Two pipelines read the same function. The test asserts identity, so a future divergence fails the suite rather than forking the answer silently.

Spec, not prose

Thresholds live where they can be tested

Weights, boundaries, band edges, rule order. All in Python, all rendered into the prompt, none of them two facts that happen to agree.

Measured, then claimed

Caching is falsifiable now

One log line per phase, greppable out of production. The number that proved the fix is the same number that would have caught the bug.

And it was reported failing

The guard did not hold

The escape hatch was designed from a measurement, enforced in code, and then re-measured and found to be insufficient. That result is on this page at the same weight as the wins, because a builder who only reports the half that worked is not reporting.

The line to take away. Determinism is not about removing the model. It is about being precise about which half of a decision belongs to it. The model reads the paragraph. Python owns the arithmetic. The moment those two get mixed, you are paying twice — once for the judgment, and again to guess at what it meant.
