The help system that reads the app

Every product has help pages. They are a copy of the product, kept somewhere else. Copies drift, and the person who changes a screen has no reason to open the page about it.

So we stopped keeping a copy. The help reads the app itself, alongside the guides we already write by hand.

Why Not Build Something Static Beside It

You could build a second thing: a help site that describes the product, written and maintained next to it. It starts correct. Then it quietly stops being correct, and the only person who finds out is a customer trying to follow it.

The app is the one description of itself that is always current, because changing it is the job. Adding a field to a form changes the app that day. Nothing changes the document about that form, unless somebody remembers.

Written guides still earn their place, but for the part the app cannot tell you: what a thing is for, what it will not do, and what to watch out for. That part changes slowly. The part that changes every week is now read instead of written.

You are not maintaining two descriptions of the same product. You are maintaining one, plus the intent behind it.

What It Reads, And What It Refuses

A browser signs in as a real account, visits every page, and reads what a person would see. It takes chrome and only chrome.

Reads

The shape of the page

  • Headings
  • Buttons, and where links go
  • Field labels and placeholders
  • Dropdown options
  • Column headers
Never reads

Anything that belongs to somebody

  • Table cells
  • Paragraphs of content
  • Anything typed into a field
  • Password fields, at all
  • External links

That split is the whole discipline. The scan runs against a live account, so anything it lifted off a row would become help text for every customer. A button label is the same for everybody. A row is not.

When It Doesn't Know, It Says So

The assistant used to be told to answer from what it already knew when the documents came up short. That is an instruction to be confidently wrong. Asked where to update an agent's instructions, it described the evaluation pipeline, because that was the nearest thing it knew containing the word.

It now says the documentation does not cover it, and names the closest page it did find.

Before
where can I update my agent's instructions
Quality Analysis runs five agents: Instructions, Ethos, Bias, Safety and Synthesis, producing a weighted score.
After
where can I update my agent's instructions
The documentation doesn't cover that. The closest page I found is the Custom Rubric Form. Wrong direction, but it isn't pretending.

A short honest miss beats a confident guess. The second one sends you looking for a button that may not exist.

What Is Still Open

  • Anything behind a click. Pop-ups and wizard steps are invisible to a scan that visits pages rather than driving them. The agent page only shows its instruction field once Edit is pressed.
  • Pages that need an id. A detail page has no address until something supplies one, so the scan is told where to find one. That is the one piece still kept by hand.
  • Intent still needs a person. The scan can tell you a button called Edit exists. It cannot tell you when to use it, or what it costs you.
  • One ranking case still loses. Ask where to update an agent's instructions and the answer is in the index, but four written guides outrank it. The next move is letting the assistant look twice rather than trusting one list.
