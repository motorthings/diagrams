The help system that reads the app

Every product has help pages. They are a copy of the product, kept somewhere else. Copies drift, and the person who changes a screen has no reason to open the page about it.

So we stopped keeping a copy. The help reads the app itself.

01Why not build something static beside it

You could build a second thing: a help site that describes the product, written and maintained next to it or in it. It starts correct. Then it quietly stops being correct, and the only person who finds out is a customer trying to follow it.

The app is the one description of itself that is always current, because changing it is the job. Adding a field to a form changes the app that day. Nothing changes the document about that form, unless somebody remembers.

So nothing is written by hand. An agent reads the running app and rebuilds the help from it, so the help is only ever as old as the last change.

There is no second description to maintain. The product is the documentation.

03What it reads

A web crawler signs in as a real account and travels the frontend, confirming the UI. A code crawler reads the backend to find how the app works.

The frontend answers where a thing is and how to do it. The backend answers how the app works.
