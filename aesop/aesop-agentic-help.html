AESOP · Help

The help system that reads the app

A help assistant cannot answer a question whose answer lives only in the interface. Asked where to update an agent's instructions, the AESOP help panel described the evaluation pipeline instead, because no document said where that screen was.

More writing does not fix that. Reading the app does.

Two Corpora, One Index

Written guides carry intent. What a thing is for, what it will not do, the caveats somebody learned the hard way. They change slowly, which is why they are worth writing down.

Pages read off the running app carry surface. Every route, its sections, the controls on it. They change every time somebody ships a change, which is why nobody keeps them current by hand.

Both land in the same index and both are retrievable. A question about how something works pulls a guide. A question about where something lives pulls a page.

The Crawler

A headless browser signs in, walks every route in the app tree, and reads the DOM. One file per page, written where the indexer already looks.

The hard rule is what it refuses to read. The crawl runs as a real account, so anything it takes off a row is that account's data and would become help text for every customer. It reads chrome and only chrome.

Reads
The shape of the page
  • Headings
  • Buttons and link targets
  • Field labels and placeholders
  • Select options
  • Column headers
Never reads
Anything that is somebody's data
  • Table cells
  • Paragraphs
  • Any input's value
  • Password fields, at all
  • External links

Two more decisions came out of running it. Chrome is dropped by counting. A control on most pages is the sidebar; a control on a few is content. Without that filter every document carried the same twenty navigation links. One page is one block. Split into a heading per list, a page became three thin chunks and a question stopped matching it. Read as a single dense block, it matches.

A field labelled System Instructions answers the question. Nobody wrote it for the docs. It is in the UI, and it changes with the UI.

Retrieval

Two arms run over the same chunks and their results are fused by rank.

The vector arm returns what sits nearest the question in embedding space. The keyword arm counts how many of the question's words appear literally in the chunk, ignoring words of three characters or less so that a question's grammar drops out without a stopword list to maintain.

Fusion is reciprocal rank, one over sixty plus the place, summed across both arms. A chunk both arms like wins. A chunk only one arm likes still surfaces, which is the point of having two.

score = 1/(60 + vector_place) + 1/(60 + keyword_place)

Not a weighted sum of the two scores, because a cosine similarity and a word count are not the same unit. Any sum of them needs a constant somebody has to choose and revisit. Rank needs no constant.

Fixed
where do I add a new agent
The agent-creation page now ranks first. It used to lose to a written guide.
Fixed
where is the custom rubric page
The rubric page is now in the top five. It was absent entirely.
Still loses
where can I update my agent's instructions
The answer is in the index and ranks below four written guides, because "agent" and "instructions" appear in most of them and the tie goes to distance.

Coverage is solved. Ranking is the part still worth work, and the honest fix is not more keyword tuning.

Grounded Refusal

The system prompt used to end with an instruction to answer anyway.

If the context doesn't contain enough information, use your core knowledge to answer.

That guarantees a confident answer to a question the corpus cannot answer. In this case the core knowledge block had one sentence containing the word Instructions, a description of the evaluation pipeline, and the model reached for it.

Before
where can i update my agent's instructions
The Quality Analysis pipeline runs five agents: Instructions, Ethos, Bias, Safety and Synthesis, producing a weighted score.
After
where can i update my agent's instructions
The documentation doesn't directly cover updating an agent's instructions, but the closest relevant page is the Custom Rubric Form. An honest miss, and the reader knows where to look next.
The line that matters. A short honest miss beats a confident guess. A wrong answer sends somebody looking for a control that may not exist, and they will trust the next wrong answer too.

What Is Still Open

Blind spot
Anything behind a click
Modals, wizard steps, tabs not yet opened. The crawler visits pages, it does not drive them. The agent page's instruction field only exists once Edit is pressed.
Blind spot
Pages that need an id
A detail page has no URL until something supplies one, so the crawler is told where to find one. That rule is the single thing still kept by hand.
Inherent
Prose still rots
The crawler cannot describe intent, cost, or when to use a thing. That half is still written by a person. It is now the smaller half, and it changes slowly.
Next
Let the assistant look twice
One ranked list decides the answer today. Giving the model tools over the index, so it can look again or admit it found nothing, is the fix for the paraphrase case that ranking keeps losing.
