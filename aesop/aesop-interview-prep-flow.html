Interview Prep Flow

Ten gated phases. You approve each output before the next one runs. Every artifact feeds a shared knowledge base that becomes the voice agent you rehearse against before you walk in.

Each phase is designed to spend tokens only on what a prior phase couldn’t determine. Where the JD or research gives a deterministic answer — stack keywords, seniority, regulated industry, enterprise-only tools — code extracts it. LLMs fill the gaps code can’t.

01
Research
Company context + each person in the room

Deep research on the company: AI posture, tech stack, regulatory obligations, competitive position, what the job posting tells you about what’s broken. Then the same pass on each person you named — career arc, public writing, what question candidates never answer for them.

02
Knowledge Audit
Deterministic pre-check first, then LLM gap analysis

Before spending a single token, code extracts what it can: stack keywords from the JD, seniority level, regulated industry flag, assignment presence, people count. Hard gaps (no JD, no assignment) are named without an LLM call. The LLM then audits only what code couldn’t determine — internal architecture, vendor contracts, failure history — and names an assumption for each gap.

Audit table + gap list
▲ Gate — review before continuing
03
Brief
Your working theory, stated with its assumptions

Synthesizes research and audit into a prep brief. Every assumption is named explicitly — “I don’t have X, so I’m assuming Y.” This is what you’d tell the panel before you start the demo: what you know, what you inferred, and where you’d push back if you’re wrong.

Editable brief
▲ Gate — edit before continuing
04
Flaw Check
Hostile review before the idea leaves the room

A skeptic reads the brief and looks for holes: wrong stack assumption, ignored constraint, overreach given the seniority of the role, something that’ll get you immediately challenged in the room. Severity-ranked findings: critical, moderate, minor.

Findings by severity
▲ Gate — review before continuing
05
Build Proposal
Demoable stack only — enterprise-only tools filtered out

Code scores the stack before the LLM sees it. Tools found in the JD are classified as demoable (free account available) or enterprise-only (Oracle, SAP, Salesforce — no free access). The LLM only proposes from the demoable set and falls back to open-source equivalents when the company’s stack isn’t accessible. The honest limit — what the build can’t cover without internal access — goes into the presentation explicitly.

▲ Gate — review before continuing
06
Spec Doc
Self-contained build prompt for Claude or Cursor

Generates a complete build prompt: the full context, the artifact requirements, the stack choices, the constraints, the output format. Paste it into Claude Artifacts or Cursor and the artifact builds itself. The spec is platform-aware — it outputs in the form the target builder expects.

Editable spec doc
▲ Gate — edit before continuing
07
Deck + Talk Track
Minimal slide text — script in speaker notes, not on the slide

Slides carry only a headline and 2–3 bullet prompts. The full talk track goes in speaker notes. Demo slides (4–5) are bare — headline and one number, because the screen leads. Also generates a structured Claude Design prompt: Mulish tokens, company brand color, 16:9 HTML artifact, slide-by-slide visual direction. Paste it into Claude Design and get a polished deck without additional context.

Editable deck + speaker notes + Design prompt

08
System Prompt
The voice agent’s identity: shaped like the room

Writes the ElevenLabs agent system prompt. The agent is voiced as the panel: it knows the company, has read the brief, asks the questions a skeptical hiring manager would ask. Difficulty dial built in — softball, normal, adversarial. Edit to match who’s actually walking in.

Editable system prompt
▲ Gate — edit before continuing
09
KB Assembly
Everything in one knowledge base, capped at 295K chars

Concatenates all phase outputs plus any documents you uploaded — JD, assignment, uploaded research decks, notes — into a single knowledge base. The agent will be able to cite any of it during rehearsal. Progress bar shows how full the 295K ElevenLabs limit is.

▲ Gate — review before continuing
10
Create Voice Agent
Upload KB, spin up the rehearsal agent, walk in prepared

Paste your ElevenLabs API key. AESOP uploads the knowledge base, creates the Conversational AI agent, and returns a dashboard link. Open ElevenLabs, press play, and run your presentation against a panel that sounds like the room and has read everything you gave it.

Run as many times as you need. Each rehearsal is an eval on yourself.

Live rehearsal agent

One knowledge base. Code where possible, LLM where necessary.

Every document you upload — JD, assignment, research decks, notes — and every phase output feeds the same KB. Upload more any time before phase 9 runs. The agent knows everything you gave it, and nothing you didn’t.

Each phase is designed to spend tokens only on what the prior phase couldn’t determine. Stack classification, seniority, regulated-industry detection, slide headline extraction — all deterministic. LLMs synthesize research, name assumptions, write scripts, and build system prompts. Nothing twice.
