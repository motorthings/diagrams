Monitor · Deterministic Engine

The same trace, scored the same, every time.

The part of the monitor that decides whether an agent misbehaved is not a model. It is a set of pure functions over the retrieval trace — what the agent pulled, and the metadata on it. No LLM, no sampling, no temperature. Run it twice on the same call and you get the same finding twice.

That is what makes a finding defensible: it reproduces, it explains itself, and its own error rate has been measured.

It reads the trace your stack already emits

LangChain
The retriever's output
A LangChain retriever returns the documents it pulled, each with its metadata. That returned set, exposed through LangChain's callbacks, is the trace the engine reads. Nothing is re-platformed.
Databricks
Vector Search results
Databricks Vector Search returns each chunk with its metadata columns — source, jurisdiction, effective dates, authority. The engine compares exactly those fields. The RAG already produces them.
The boundary
It needs the retrieval logged
The honest requirement: the RAG logs its retrieval step. LangChain exposes it; if it is captured, the engine runs. If the trace is thin, the engine says so rather than guessing.

The checks and their logic

scopeJurisdiction or operating company crosses the callerA chunk's jurisdiction or operating company differs from the caller's stated scope. A PSCo document answering an NSPM caller.
freshnessOutside its validity windowA chunk's effective dates do not contain the call date, or it is flagged superseded. A stale tariff beating the current one.
authorityA governing document was skippedFor the topic, a higher-authority document exists in the index, but the retrieval used a lower one.
contradictionThe sources disagreeTwo retrieved chunks on the same topic carry differing claims, so the answer rests on which one won.
entityThe wrong value, structurallyA transposed number or a stale figure, caught by rule against a known-good value, not by meaning.

Why you can be confident

Reproducible
Pure functions
Same trace in, same findings out, every run. No sampling, no temperature, no model call. A disputed finding can be re-run and reproduced exactly.
Explainable
It names the rule
Every finding cites the chunk, the field, and the rule it broke — "chunk X is NSPM, caller is PSCo." An auditor checks each one by hand.
Measured
A known error rate
Scored against labels: 0.944 precision on 240 calls. The control has its own measured error rate, which is the first thing an auditor asks for.
The reads-the-trace line is the whole point. A judge that reads the answer's prose is a second model, and a second place for things to be inconsistent. This engine reads the sourcing — what was retrieved, from where, under whose authority, as of when — and compares fields. That is arithmetic, and arithmetic re-runs the same way. The probabilistic judge stays available for the semantic failures a trace cannot show, but it is not what the monitor leans on.
