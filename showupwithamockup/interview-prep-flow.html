Show Up With A Mockup — The five stages

Interview Prep Flow

The room first, then five decisions. You approve each one before the next runs. Every artifact feeds one knowledge base that becomes a voice agent voiced as your actual panel — rehearsed in the app, not on a dashboard link.

Each step spends tokens only on what a prior step couldn’t determine. Where the JD or research gives a deterministic answer — stack keywords, seniority, regulated industry, enterprise-only tools — code extracts it. LLMs fill the gaps code can’t.

00
The room
Extract and verify the panel before anything runs

Upload transcripts, phone-screen notes, recruiter emails. Code pulls the speaker names out — deterministic regex, no LLM — collapses partials (“Luke” → “Luke Priiner”), and keeps two people who share a first name separate. “Get details” then web-searches each person across four source types — LinkedIn, press, org pages, conference bios — and returns a confidence level, not a guess.

You check who is actually in the room. That list is the cast — and the rehearsal agent will not run without it.

01
What I know
Research, then audit. Code first, gaps named.
Research

Deep research on the company: AI posture, tech stack, regulatory obligations, competitive position, what the job posting tells you about what’s broken. Uploaded transcripts and notes are primary sources — the model quotes an interviewer’s exact words over a scraper’s summary. Then the same pass on each person in the room: career arc, public writing, the question candidates never answer for them.

Research summary
Knowledge audit

Before spending a single token, code extracts what it can: stack keywords from the JD, seniority level, regulated industry flag, assignment presence, people count. Hard gaps are named without an LLM call. The LLM then audits only what code couldn’t determine — internal architecture, vendor contracts, failure history — and names an assumption for each gap.

The brief
Your theory, then a hostile review. Statutes verified.
Brief

Synthesizes research and audit into a prep brief. Every assumption is named explicitly — “I don’t have X, so I’m assuming Y.”

If the brief cites a statute, the check verifies it against live sources — in force, amended, repealed, or superseded — and stamps each as of today. Only what comes back clear may reach the deck.

Editable brief + verified statutes
Flaw check

A skeptic reads the brief and looks for holes: wrong stack assumption, ignored constraint, overreach given the seniority of the role, something that’ll get you immediately challenged in the room. Severity-ranked findings: critical, moderate, minor.

03
What to build
The artifact as parts, then a paste-ready spec.
Build proposal

Code scores the stack before the LLM sees it. Tools found in the JD are classified as demoable (free account available) or enterprise-only (Oracle, SAP, Salesforce — no free access). The LLM only proposes from the demoable set and falls back to open-source equivalents when the company’s stack isn’t accessible.

The artifact comes back as parts, not a paragraph — a name, a one-liner, each component and what it shows, and the thread that ties them into one story. The honest limit — what the build can’t cover without internal access — goes into the presentation explicitly.

Proposal + classified stack
Spec doc

Generates a complete build prompt: the full context, the artifact requirements, the stack choices, the constraints, the output format. Paste it into Claude Artifacts or Cursor and the artifact builds itself. The spec is platform-aware — it outputs in the form the target builder expects.

04
The deck
Headlines only, script in notes, bound by three disciplines

Slides carry only a headline and 2–3 bullet prompts. The full talk track goes in speaker notes. Demo slides are bare — headline and one number, because the screen leads.

Three disciplines bind this step. Critical and moderate findings from the flaw check are non-negotiable — the deck may not repeat them. Only statutes the brief verified as current law may be named; everything else reads “confirm with legal.” And a brand or design guide in the knowledge base drives the Claude Design prompt — its fonts, colours, and type rules reproduced in full, not summarised.

05
The rehearsal agent
A closed cast and one knowledge base, both feeding the agent
System prompt

Writes the ElevenLabs agent system prompt from the real cast. The agent plays each named person by name and role — a closed cast, no invented panel members — and grounds every pushback question in something specific: a quote, an incident, a named constraint. Difficulty dial built in — softball, normal, adversarial, with a hard-mode pile-on and a yes/no hold rule.

This step refuses to run without people. A rehearsal against invented stand-ins is worse than none, so the cast is a precondition, not a suggestion.

Editable system prompt
KB assembly

Concatenates all phase outputs plus any documents you uploaded — JD, assignment, uploaded research decks, notes — into a single knowledge base. The agent will be able to cite any of it during rehearsal. Progress bar shows how full the 295K ElevenLabs limit is.

Rehearse
Spin up the agent, rehearse in the app, walk in prepared

Paste your ElevenLabs API key. The app uploads the knowledge base and creates the Conversational AI agent, then serves the rehearsal in the app — an embedded voice widget on its own page, the roster of who’s in the room above it. No dashboard link, no separate tab. Press start and run the presentation against a panel that sounds like the room and has read everything you gave it.

Run as many times as you need. Each rehearsal is an eval on yourself.

Live rehearsal agent

One knowledge base. Code where possible, LLM where necessary.

Every document you upload — JD, assignment, research decks, notes, brand guides — and every step’s output feeds the same KB. Upload more any time before the rehearsal agent runs. The agent knows everything you gave it, and nothing you didn’t.

Each step spends tokens only on what the prior step couldn’t determine. Stack classification, seniority, regulated-industry detection, slide headline extraction — all deterministic. LLMs synthesize research, name assumptions, write scripts, and build system prompts. Nothing twice.

Three threads run the whole way down. The people are the spine — extracted, verified, and voiced by name, never invented. The law is never asserted from memory — every statute is checked, and only cleared ones reach the deck. And a brand or design guide in the KB drives the deck’s look, reproduced in full rather than summarised.
