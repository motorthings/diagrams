The Evaluation Engine
The hardest problem in AI: how do you evaluate an AI agent when the agent itself cannot be trusted to self-assess? AESOP answers with 20+ specialized evaluation agents, each scoring a different dimension — then a programmatic scoring engine applies weighted tiers, veto rules, and certification levels. No LLM self-assessment. Every score is auditable.
20+ evaluation agents 6-stage pipeline Scoring: 4 dimensions + veto Cave of Shadows (red-team) The Hydra (parallelized swarm) Bias Probe (differential testing) Sentinel (QA test gen) Drift Detection (6 types) RAG Help System (pgvector) Custom Rubric engine Black Box Investigation Forge Repair agent
6-stage pipeline from discovery through production monitoring
Scoring engine: Tier 1 (1.5×) + Tier 2 (1.0×), hard veto at 75
Cave of Shadows: adversarial red-team with attack personas
Hydra: parallelized swarm running dozens of test scenarios simultaneously
Bias Probe: paired differential testing detecting treatment disparity
Sentinel: generates dual-output QA test plans from evaluation results

Strategic Simulations
Simulating AI Transformation
Two multi-agent simulations that turn the "what does AI transformation actually look like" question into concrete, repeatable, falsifiable answers — one about the economics, one about the change process.
AI Profit Paradox · legal-sim
An AmLaw 100 firm adopts AI — and pricing decides everything
A multi-agent simulation of a commercial-litigation firm (~900 attorneys, ~$1.9B revenue) adopting AI across 16 sprints. The industry / legal-AI-company view: the question it answers is about the market, not one firm's balance sheet.
2-track A/B contest 3 levers: pricing · comp · seams 30 tests · 8/8 signals deterministic · cross-process safe
The AI Profit Paradox: hourly billing makes AI a net loss (compressed hours = lost revenue); alternative fee arrangements make the same AI a net win. Same tool, same people, same adoption.
Pricing is the master lever — ahead of comp and seams.
Comp/origination moves adoption (40→49.6%) but not outcomes — the adoption paradox.
The seam a tool attacks decides whether it's valuable now (codifiable: citation, research) or stalls at the partner (tacit: drafting judgment).
On outcomes, discovery beats design on tacit seams; design ties on codifiable seams — "design drives adoption, discovery drives outcomes."
For legal-AI companies: does your "time savings" pitch survive the billable hour?
Two adversarial reviews clean; deterministic and reproducible.
The AI Transformation Experiment
Two tracks, same company, different change processes
Runs two identical copies of Progressive Insurance through 16 quarterly sprints of AI transformation — one via Stuart Winter-Tear's organic discovery framework, the other via traditional change management (Kotter / Prosci / McKinsey). Same hurricanes, same attrition, same market cycles. The only variable is how change happens.
16 quarterly sprints 2 tracks, 1 company OCEAN psych + Kahneman/Tversky biases calibrated to real Progressive filings parity on codifiable seams decisive A-edge on tacit seams
Grounded in real financials, Glassdoor data, and organizational psychology — so the outputs are evidence, not illustration.
Post-fairness-fix: Track B's attrition debt collapsed (~22→5) — a tie on codifiable seams, not an 18-pt loss; A still wins tacit (correct).
Power analysis: the codifiable tie is parity, not an underpowered B-edge — ~0.2pp with a CI straddling zero; more seeds won't flip it.
The lever that actually moves the codifiable cell is design accuracy / the tacitness mix — not sample size.
Discovery surfaces more translation debt and trust cascades; design drives adoption, discovery drives outcomes.
Deterministic; canonical post-fix runs on seeds 42 + 7.

Patterns That Span Every Project
These patterns appear across every platform — they're not one-off implementations but reusable architectural primitives ported between projects.
Multi-Agent Evaluation
  • Built in AESOP, ported to Legal-OS
  • Parallel evaluator agents — each scores a different dimension
  • Programmatic scoring engine — never trusts LLM self-assessment
  • Weighted tiers + hard veto + certification levels
  • Drift detection with baseline comparison and severity alerts
  • Same scoring formula used in both platforms
RAG Help Systems
  • Built in both AESOP and Legal-OS
  • Voyage AI embeddings → pgvector similarity search
  • LLM-generated answers with source references
  • Slide-out chat panel with suggested questions
  • Local FAQ fallback when API unreachable
  • Same architecture, same indexing pipeline
Governance Architecture
  • Append-only audit trails — every decision recorded
  • Row-Level Security — client data isolation at the database
  • Human-in-the-loop gating with configurable thresholds
  • Compliance readiness: ABA 512, SOC 2, ISO 42001
  • Traceability: full lineage from input to output
Provider Resilience
  • LLM provider abstraction — one interface, multiple backends
  • Automatic fallback on auth errors
  • Per-function provider overrides for cost optimization
  • DeepSeek for cost (~10x cheaper), Anthropic for quality
  • Pricing tables with per-model token cost calculation
